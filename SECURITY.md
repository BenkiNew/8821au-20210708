# Security policy

## English

Security reports are reviewed against the current `main` branch and latest fork
release. Older releases do not have a separate security maintenance branch.
Compatibility and hardware validation limits are listed in
[the validation matrix](docs/VALIDATION.md).

For a suspected vulnerability, use
[GitHub private vulnerability reporting](https://github.com/BenkiNew/8821au-20210708/security/advisories/new).
Do not post exploit details or sensitive logs in public Issues or Discussions.

Include the driver commit/release, exact kernel, adapter USB ID, affected code,
reproduction steps and potential impact. Remove credentials and personal data.
The maintainer will assess the report and coordinate any fix and disclosure;
there is no guaranteed response time or security audit coverage.

For ordinary build or connection problems, see [SUPPORT.md](SUPPORT.md).

## Українською

Повідомлення про вразливості перевіряються щодо поточної гілки `main` та
останнього релізу форку. Для старих релізів немає окремої гілки безпекового
супроводу. Межі перевіреної сумісності наведено в
[таблиці перевірок](docs/VALIDATION.md).

Про підозрювану вразливість повідомляйте через
[приватний звіт GitHub](https://github.com/BenkiNew/8821au-20210708/security/advisories/new).
Не публікуйте деталі експлуатації чи чутливі логи в Issues або Discussions.

Зазначте commit/реліз драйвера, точне ядро, USB ID адаптера, проблемний код,
кроки відтворення та можливі наслідки. Приберіть облікові й персональні дані.
Мейнтейнер оцінить звіт та узгодить виправлення і розкриття; гарантованих
строків відповіді або повного безпекового аудиту немає.

Звичайні проблеми збірки чи підключення описані в [SUPPORT.md](SUPPORT.md).
